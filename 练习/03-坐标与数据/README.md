## 一个点，从相机坐标换到世界坐标

约定相机到世界旋转 90°，平移 `(1,2)`。旋转矩阵是：

```text
R = [ 0  -1 ]
    [ 1   0 ]
```

相机中的点 `(1,0)` 先旋转为 `(0,1)`，再加平移，得到世界点 `(1,3)`。逆变换先减去平移，再乘 `Rᵀ`，回到 `(1,0)`。这个例子里所有位置使用相同单位，旋转不改变长度。

再做二连杆：`l1=l2=1，q1=π/2，q2=-π/2`。第一段末端在 `(0,1)`，第二段向右伸长 1，所以总末端是 `(1,1)`。

写下你自己的计算过程，并解释为什么不能省略坐标系和单位。

## 同一批示教，有两种不同测试问题

[episodes.csv](episodes.csv) 是原创合成的 12 条轨迹元数据：3 个场景、2 种杯子。它只有划分字段，没有真实机器人视频或动作。

| 方案 | 训练轨迹 | 测试轨迹 | 想回答什么 |
|---|---|---|---|
| 每场景留出一条 | e01–e03、e05–e07、e09–e11 | e04、e08、e12 | 已见场景的新轨迹能否做好？ |
| 留出整个场景 | e01–e08 | e09–e12 | 没见过的场景能否做好？ |

两种方案都没有训练/测试轨迹 ID 重叠，第二种还没有场景重叠。模型归一化所需的统计量只能从训练数据得到。若把同一条示教的相邻帧随机分到两边，可能让测试过于容易。

把这两种划分另存为自己的 `split.csv`，增加一列 `train/test`。然后说清：留出场景与留出物体是不同问题；这份第二方案仍见过 cupA、cupB，不能据此宣称对未见物体泛化。
