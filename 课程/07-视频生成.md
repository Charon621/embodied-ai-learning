# 第7章：视频生成

[课程首页](../README.md) · [上一章](06-世界模型与规划.md) · [下一章](08-视频世界模型与动作.md)

时间结构、视频压缩与条件共同决定生成结果怎样连贯和可控。

## 这一章怎么学

1. **先做的事**：先读帧数与 token 预算，再做 [视频评测练习](../练习/视频评测示例.md)；设备足够时再选做真实生成。
2. **再读的资料**：[Video Diffusion Models](https://arxiv.org/abs/2204.03458) 的时间结构与 [VBench](https://vchitect.github.io/VBench-project/) 的评测维度；工程项目放选读。
3. **可以继续的标准**：能算 token 数，区分画面质量与运动正确，并为一段视频写出可以观察的成功条件。

主线参考用时：16小时。第一遍先完成上面的关键练习；正文中的其他练习和选读可回头补。遇到术语先查 [速查页](../学习指南/术语速查.md)。

## 正文讲解

本章主线预算 16 小时、2 周；含选读和 GPU 扩展时可安排 24–40 小时，时间是教学估计。视频生成学习 `p(video | condition)`，必须同时处理外观、运动、条件符合度与成本。它能为世界模型提供表示或生成组件；要成为可用的机器人预测器，还要另验动作响应与闭环后果。完成本章不需要先走机器人线。

## 开始之前：这一章学会什么

前置：[第2章](02-视觉与Transformer.md) 视觉/Transformer 与 [第4章](04-扩散与FlowMatching.md) 扩散/Flow Matching。自测：把一个 `16×256×256` 视频在时间上压缩 4 倍、空间上各压缩 8 倍，再按 `1×2×2` latent patch 切分，共有多少 token？答案是 `4×16×16=1024`，假设维度整除、忽略特殊边界处理。再解释 VAE、DiT、速度回归、CFG 分别属于哪一层。两题都能独立完成后开始。

这一章学会什么：① 为 T2V 与 I2V 各画一张数据流；② 算清一个时空 token 预算，比较全注意力与分解注意力；③ 设计只有一个变量变化的采样消融；④ 写出至少四类失败的评测规约；⑤ 读官方代码，定位编码、条件、生成网络、采样与解码入口。终点是一份可执行实验计划与审计报告，GPU 实验属于选做。

## 1. 视频样本：帧数不等于时间，漂亮单帧不等于连贯运动

图像的状态可记作 `H×W×C`，视频多一个时间轴 `T`。相同 16 帧以不同 FPS 播放，对应的物理时长不同；训练时抽帧步长改变了模型实际观察到的运动速度。帧间存在遮挡、视角变化、身份保持与事件顺序。独立生成 16 张好看的图，无法自动获得正确的跨帧关系。

最小样本说明应写：片段时间区间、帧数/FPS、抽帧方式、分辨率/裁剪、文本或图像条件、来源与使用许可。数据去重和切分以源视频/主体/场景为单位，避免同一长视频的近邻片段同时进入训练和测试。配文若只描述外观，模型不一定学到运动和顺序。本节的数据说明是课程练习，不声称单一标准适用于全部模型。早期 [Video Diffusion Models](https://arxiv.org/abs/2204.03458v2) 将图像扩散扩展到视频，可用来观察时间建模与条件延长问题。

## 2. 时空结构：先理解预算，再比较架构

常见流程为 `video → video autoencoder → noisy latent → conditional denoiser/velocity network → latent → decoder`。二维逐帧编码便于继承图像表示；时空编码器可同时压缩时间和空间。高压缩率能减少 token，却可能损失细小动作或快速变化。不要仅看生成器，先检查真实视频经过编码再解码的重建，才能定位上限。

若 latent 网格为 `T'×H'×W'`，patch 为 `pt×ph×pw`，整除情况下 token 数 `N=(T'/pt)(H'/ph)(W'/pw)`。全注意力的注意力矩阵随 `N²` 增长；增加时长可能比增加参数更快占用内存。分解空间和时间注意力可降低部分开销，但信息混合路径与完整全注意力不同；局部窗口、稀疏结构也有跨窗口传播的权衡。实际总成本还包括网络宽度、前馈层、批量和实现，不能仅用 `N²` 宣称具体显存。

位置编码需要表达空间与时间位置，帧率、长宽比等可以成为附加条件。模型使用 DiT 或 U-Net，与它使用扩散或流目标是两项选择。[Stable Video Diffusion](https://arxiv.org/abs/2311.15127v1) 可读作数据与训练阶段的案例：它讨论图像预训练、视频预训练和高质量微调。论文覆盖的任务与某个具体发布 checkpoint 的任务可能不同，运行前必须读该权重的模型卡。

## 3. 条件与控制：提示、首帧、轨迹提供不同约束

Text-to-video（T2V）由文本规定场景和事件；image-to-video（I2V）增加给定图像，通常强化起始外观与布局。首尾帧约束、深度/姿态、相机或物体轨迹提供更具体的控制信息，但必须核对模型是否真正以此为输入，不能把文本中写“相机向左”当作精确相机控制。

条件注入可能采用 cross-attention、特征调制或 latent 拼接。若拼接参考 latent 或已知帧，需要同时定义掩码与噪声处理，使模型分清哪些内容已知、哪些待生成。CFG 可改变条件影响，却不会保证物体身份、几何关系或物理规律。控制能力应通过改变一个输入变量来检验：同一首帧、同一随机种子、同一采样设置，仅改变运动方向，检查输出是否沿预定方向改变。

参考 [Wan2.1 官方仓库](https://github.com/Wan-Video/Wan2.1) 的任务和参数入口，辨认 T2V、I2V 与首尾帧生成；不要把不同权重写成一个模型全都支持。现代项目迭代快，本课程只把已核验的公开仓库作为选读，未独立复现其效果，也不自动启用仓库中的提示扩写 API。

## 4. 采样实验：固定条件，让结论只回答一个问题

视频生成可用扩散类或流类目标。采样器决定怎样沿噪声到数据的过程前进；第4章 的一步 Euler 很直观，但高维模型的实际采样实现还可能使用其他求解器、时间日程或预测参数化。不要随意互换 scheduler：先查它接受的是噪声、干净样本还是速度，以及状态的缩放和时间方向。

一个合格的步数消融固定模型版本、文本、首帧、种子、帧数、FPS、分辨率、引导系数及解码设置，只改变步数。另一次引导消融再单独改变 guidance。记录端到端耗时和峰值显存的测量范围：权重载入是否计入、是否 CPU offload、是否缓存。没有实际设备运行就填“未测”，不能根据参数量推算可用显存。少步数输出更模糊，也可能更稳定；这属于待检验假设，必须给出观察证据。

选读 [Open-Sora 官方仓库](https://github.com/hpcaitech/Open-Sora)，按固定版本阅读配置、视频 autoencoder、训练和推理入口。Open-Sora 是该作者团队的开源工程，不等同于 OpenAI Sora。完成一次代码追踪，比再收集十个演示名字更有价值。

## 5. 评估：质量、多样性、运动与控制需要分开测

单个“总分”会掩盖失败。建议至少保留四列：画面质量；跨帧主体/背景一致性；动作与事件顺序；输入条件符合度。再增加你任务特有的一列，例如轨迹误差。一个静止片段可能非常稳定，却没有执行要求的动作；两个物体先后关系错误，也可能看起来流畅。

[FVD](https://arxiv.org/abs/1812.01717v2) 在视频特征空间比较生成与真实样本分布。它不是逐条视频的物理正确率，特征提取器、样本量、帧数、FPS 与预处理都影响可比性。没有同协议参考集时不要强行报 FVD。若只看图像特征指标，会遗漏部分时间问题。

[VBench](https://vchitect.github.io/VBench-project/) 提供分维度视频生成评测入口。先阅读每个维度的定义与适用条件，再采用其中一部分；不要把页面归一化展示图当原始得分。课程还要求人工盲评：隐藏模型标签，随机顺序展示，同一规则由至少两位评分者评，保留分歧和失败样本。若只有自己评，注明单人且未盲。视觉逼真、动作控制与机器人闭环成功必须分开陈述。

## 按序阅读与交付

1. **必读 Video Diffusion Models**：看时间结构和条件生成，预计 2–3 小时；交一张张量形状图。
2. **必读 Stable Video Diffusion**：看数据整理与三阶段训练，预计 2–3 小时；交数据处理与训练阶段表。
3. **必读 VBench**：读四个与你任务相关的维度，预计 1–2 小时；每列写测量对象与失效条件。
4. **选读 FVD**：需要分布评估时读，预计 2–3 小时；有同协议参考数据才运行。
5. **选读 Open-Sora 或 Wan2.1**：只选一个做源码追踪，预计 4–6 小时。权重许可证、任务与实际硬件要求按你固定的版本检查，不要求同时复现两套工程。

## 最小练习、低算力替代与验收

无需下载权重的必做练习：设计 12 条原创提示，包含单物体运动、遮挡后重现、两个事件的先后、相机运动四组；为每条预定义“成功可观察条件”和至少一种失败。交 `video-plan.md`、`token-budget.csv`、`evaluation-rubric.md` 和一份官方源码入口表。预算表需比较两个时长/分辨率设置，写出压缩率、patch、token 数与近似注意力比例；不能伪装成硬件实测。

有合适设备再选做：固定一个已公开权重和 commit，以三种采样步数、两个种子生成同一提示，输出全部六个结果、完整配置与失败记录。执行前自行确认许可、磁盘和硬件；本课程的标准库实验不会触发这些下载。无 GPU 可对已有且许可允许查看的官方演示做人工失败标注，但它只能练评估方法，不能证明你复现了模型；将选做运行结果标记为“未运行”。

通过条件：两张数据流无层级混淆；两个 token 预算计算正确；12 条提示各有可观察判据；四维规约能区分“静止但稳定”与“正确运动”；代码入口可追溯到固定版本。选做实验还需种子和参数齐全，展示全部结果，禁止只挑最好片段。

## 常见误区、进阶问题与可lip补充阅读

误区：视频帧数当秒数；逐帧高质量当视频高质量；文字提示当精确动作输入；论文任务当全部发布权重都支持；榜单归一化数值当原始可比指标。进阶：长片段拼接如何维持身份？编码器重建失败如何与采样失败分离？如何设计相机运动与物体运动的反事实对照？生成视频若用于机器人规划，怎样证明对动作改变有响应，并测出累积误差？后两题转入 第8章/第9章。

对应可lip `10–13`，用于补充Flow Matching、信息流、AdaLN和位置编码。这里补上视频数据、时空压缩、条件控制、采样比较与评测。接着读 [第八章：视频世界模型与动作](08-视频世界模型与动作.md)，理解视频怎样与具身智能连接；只学视频的读者按 [专题路线](../学习指南/专题学习.md) 前进。
