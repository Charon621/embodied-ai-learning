## 正文讲解

视频可以统一描述很多场景，但不同机器人的动作接口仍不同。本章沿着“动作怎样进入模型”组织阅读，避免把作品名称串成升级排行榜。建议 **16 小时**，其中约 5 小时制作一份可审计的方法与实验设计。研究资料访问与主题核验日期为 **2026-10-11**。

## 这一章学会什么

- 将论文归为“视频计划加逆动力学”“动作条件前向模型”“联合视频动作模型”，允许一个方法跨多类。
- 为每种方法标明语言、观测、本体状态、动作的条件与输出，写清动作的单位和时序对齐要求。
- 区分视频质量、动作响应、真实执行、跨环境迁移四层证据，不用演示视频代替实验。
- 设计包含失败数据、动作干预、闭环延迟和公平计算预算的验证协议。
- 读出一种 autoregressive diffusion 方法在环境时间轴和去噪时间轴上分别做了什么。

## 1. 视频作为计划：先画未来，再求怎样做到

[UniPi](https://arxiv.org/abs/2302.00111) 将语言目标和当前画面映射为未来视频计划，再用逆动力学模型从相邻画面推断低层动作。其接口可写为：

```text
video_plan ~ p(o_(t+1:t+H) | o_t, goal_text)
action_chunk ~ p(a_(t:t+H-1) | o_(t:t+H))
```

前向动力学问“做此动作之后会看到什么”，逆动力学问“要发生这段变化应该做什么”。两者训练标签和用途不同。没有动作标注的人类视频可帮助学习视觉变化，却不会自动给出某台机器人电机命令。逆动力学必须解决本体、控制尺度、观测歧义和可达性；同一帧变化也可能对应不同接触力或多个动作。

视频计划提供了人能理解的中间产物，但可视化并不保证可执行。练习时给一段推杯子计划标出三处风险：杯子运动过快、手穿过物体、摄像机运动被误当物体运动。然后写下每处要增加什么观测或执行约束，避免只评价“像不像”。

## 2. 动作作为条件：能互动不等于懂任意机器人

[Genie（2024）](https://arxiv.org/abs/2402.15391) 从未标注动作的视频中学习潜在动作接口，支持逐帧交互。其 latent action 并不天然对应机械臂关节角或牛顿。必须检查训练域、可用动作数量、可控对象，以及怎样把潜在动作映射为外部系统的实际控制。

[Cosmos-Predict2 官方仓库](https://github.com/nvidia-cosmos/cosmos-predict2) 同时列有不同条件与用途的模型，其中动作条件样例预测“给定视频与动作的未来画面”。这与直接输出动作的策略不同。前向视频预测器还需要目标评分、候选动作生成、搜索和反馈，才构成控制系统。

[Genie 3 官方说明](https://deepmind.google/models/genie/) 可作为交互式世界生成的选读案例：检查官方列出的动作空间、交互时长、多主体交互和真实地点准确性限制。官方演示证明的是所展示的交互能力，不能据此推定严格物理引擎、任意场景守恒定律或可靠的机器人接触仿真。物理仿真器和学习式视觉世界模型有不同的误差来源，选择取决于用途。

## 3. 联合视频与动作：接口更紧，评测问题仍在

“WAM”在文献中的使用并不完全一致。本课程用它指把未来世界预测与可执行动作学习连接的模型族，学习时必须看具体结构，不能用名称判定模型能力。

[Cosmos Policy](https://arxiv.org/abs/2601.16163) 将动作、未来状态和价值纳入视频模型的训练。它既能作为直接策略，也能利用未来与价值进行候选动作选择。论文特别指出，主要成功示教的分布不足以支撑稳健规划，还需要执行轨迹中的成败经验改进预测与评分。阅读时分别画出这两种部署方式，不把“模型输出未来”自动理解为“每次部署都搜索”。

[DreamZero](https://arxiv.org/abs/2602.15922) 用联合视频动作预测把视频先验和动作学习接起来，按动作块执行后用真实观测更新上下文。重点比较“联合目标”和“两个独立模型串联”的信息交换方式；对其跨任务与跨本体结论，必须保留作者定义的数据、任务和适配边界。

[LingBot-VA（v1）](https://arxiv.org/abs/2601.21998v1) 是另一个可选结构案例：视频与动作 token 在因果序列中交错，通过双流 Mixture-of-Transformers 交互，并考虑异步预测与执行。它让我们注意到：网络结构之外，观测刷新、动作块长度和实时调度也会改变真实控制结果。这些论文结果为作者报告，课程未复现其成功率。

## 4. 两个时间轴与闭环计算预算

扩散或 Flow Matching 的 `τ` 控制一次样本从噪声到数据的求解过程；环境时间 `t` 控制机器人行动和观测顺序。Autoregressive diffusion 可以按环境时间逐块生成，每块内部再沿 `τ` 去噪。把“自回归”和“扩散”当成互斥分类，会看错计算图。

设计 mask 时先列出当前时刻实际可见的 token：历史观测、当前本体状态、目标指令，以及已执行动作；规划未来时可以输入候选动作，不能读取尚未发生的真实未来帧。块内联合去噪的 token 可见性还取决于具体方法，不能简单照搬语言模型的逐 token 三角掩码。训练若允许动作头偷看部署时不存在的未来真实观测，就会造成信息泄漏。

推理预算至少含：候选动作数量、每个候选的未来长度、每块去噪步数、价值模型调用、摄像头到执行的延迟。生成帧率、动作命令频率、整段闭环延迟是不同量。计划若用了过时的观测，即使动作头很快也可能失效。执行多长的动作块才重新观察，是速度与纠错能力的取舍。

最新系统可以把多模态模块连接得更广，例如 [Cosmos 3 官方项目](https://research.nvidia.com/labs/cosmos-lab/cosmos3/) 展示统一的理解、生成、动力学与动作接口。此处将它作为进阶接口审查材料，逐项检查已发布的输入输出、代码和验证范围，不把官方产品定位等同于已完成通用具身智能。

## 5. 怎样证明视频预测真的帮助了动作

设计四层指标。第一层是视频质量：失真、时序一致性与目标遵循；第二层是动作响应：同一前态下改变动作后，模型是否给出有区别且与环境一致的未来；第三层是真实或确定性仿真中的执行：任务完成、约束违反、失败恢复；第四层是迁移：固定测试任务、场景、本体及适配数据范围。各层需要独立证据。

核心对照是保持动作骨干、训练数据和执行预算尽量一致，比较无视频监督、辅助视频预测、实际用预测规划。还应加入动作打乱或置零、视频分支冻结、失败轨迹缺失、额外推理计算等消融。若只有视频更好看而控制不变，支持的是生成改进；若控制提高但多用了数据或搜索，不能单独归因于世界预测。

## 动手练习与完成标准

建立 `video-world-model-audit.md`，选 UniPi、V-JEPA 2-AC、Cosmos Policy、DreamZero 四个方法，制作“输入/预测空间/动作来源/任务目标/训练数据/反馈频率/推理预算/证据限制”对照表。每个关键单元格链接到论文对应章节，不能照搬第三方评价。

然后复用 [Lab 03](../labs/README-world-model.md) 的状态实验，为它设计“增加图像观测”的升级方案，给出因果 token 掩码、观测和动作对齐表、训练与测试划分、两项必要消融以及停机条件。基础作业只交设计，不下载大型模型。至少识别三种偏差：未来信息泄漏、仅成功示教造成的评分盲区、视觉变化与可执行动作不一致。

检查方式：能说明为什么 Lab 03 的反馈结果不能证明视频表征有用；每个方法正确标出前向/逆向/联合接口；方案同时包含预测和执行指标；把去噪步数、环境帧数、动作频率分开记录。完成审计表和升级方案才过关，不以观看论文视频数量过关。

## 常见误区、低算力替代与进阶问题

- 误区：视频模型拥有动作条件就是机器人策略；latent action 就是真实动作；WAM 必然替代 VLA；仅生成一条成功轨迹就证明可泛化。用接口与对照实验逐条检验。
- 低算力：用论文结构图、公开配置和 CPU 状态实验完成全部基础目标。需要 GPU 的官方推理与训练是独立选做分支，先检查许可、硬件和数据条件，再固定一个任务；这里不承诺某张显卡能运行所有模型。
- 进阶：怎样让预测保留小物体接触，同时不过度生成背景？能否在同等延迟下让模型集成提高控制？视频预训练的收益来自运动知识、数据量还是更大模型？将问题收缩为一个可证伪的假设，进入 第9章 的综合项目。
